# DFM 与成本

## 适用性判断（先于一切）

`dfm_required: true` 仅当任一成立：实体硬件、BOM、PCB、外壳/机械结构、装配、加工、生产测试、良率/供应商/材料/工装/检验要求、用户明确提出制造成本或供应链要求。

纯软件项目：`dfm_required: false` + 理由 `not_applicable`，**不生成空泛 DFM 文档**。

## 适用时的规则

- 必须先建立**可复测基线**，再由用户批准量化阈值（如 BOM/landed cost、工序数、良率、供应来源、测试/返修、交付周期）。
- 无基线 → 阻断（BLOCKED）先建基线，或由用户明确接受“无法量化的残余风险”。**不得编造数字。**

## 软件项目成本（cost_required 时）

按适用性评估：构建时间、部署复杂度、云资源、数据库容量、外部 API 费用、CPU/内存/存储、依赖维护与许可证。同样先基线后预算；成本优化不得降低安全、可恢复性、数据完整性或验收行为。

## 检查单

- [ ] 适用性已判定并记录理由
- [ ] 适用时：基线已建立（可复测）
- [ ] 量化阈值已获用户批准
- [ ] 证据可复核（脚本/数据路径 + 哈希）
- [ ] 无基线项目未出现任何百分比承诺
