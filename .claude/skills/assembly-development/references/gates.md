# 人工门禁 G0–G5

审批只认用户明确决定。**沉默、模糊回答、模型推断、subagent 建议都不构成批准。**
批准绑定 artifact 哈希：`node scripts/gate.mjs approve --gate G1 --artifact <path> --sha256 <hex>`。artifact 实质变化 → 旧批准失效。

## G0 基础设施准备（开始前）

用户逐项确认（checklist 全项通过才能开始）：
1. Git 可用（或明确接受无 Git 串行降级）
2. 语言/包管理器/运行时版本
3. 数据库、缓存、队列、对象存储等中间件（版本与可达性）
4. 本地/测试/预发布/生产环境边界
5. 远程服务器或云项目精确目标
6. 凭据存在且权限满足（**不读取、不打印、不写入凭据**）
7. 外部 API 授权、预算、配额、限流
8. CI/CD、构建与测试能力
9. 备份、恢复、日志、监控、告警条件
10. 预算/配额（云、API、人力）

随后预检（agent 验证，与用户准备分离）：`user_prepared` 与 `agent_verified` 分别记录。

## G1 需求批准（clarify 后）

- 产品简档/需求、范围与非目标
- AC（验收标准）与 NFR（性能/容量/可用性/隐私/兼容性/成本）
- 默认假设清单及其影响
- 风险初筛

## G2 方案批准（plan 后）

- 技术选型与理由
- 任务 DAG（冻结于 run/tasks/<RUN_ID>.json）
- API/schema 契约、数据与迁移方案
- 外部计费服务、成本基线
- 部署与回滚方案
- 安全测试范围（授权目标）

## G3 数据迁移批准（发布前，适用时）

- 生产数据迁移方案（expand-contract、dry-run、备份、回滚耗时与恢复点目标）
- 不适用 → 记录 `not_applicable`

## G4 生产发布批准（release 前）

- 精确环境、版本（commit/tag）、时间窗、方法（灰度/蓝绿/canary）
- 自动中止阈值、回滚条件
- 观察期与告警

## G5 最终验收（观察后）

- 交付物清单与哈希
- 已知限制与风险接受
- 用户批准 → DONE
