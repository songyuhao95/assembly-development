# 质量门禁

质量 = 硬不变量 + 行为验收 + 位置化结构审查证据 + 风险触发独立验证。**禁止**用评分、行数、覆盖率总数、agent 自评、“通过了多少条 checklist”作主要成功目标（防 Goodhart）。

## 1. 硬不变量（直接 Pass/Fail，任一失败即阻断）

- 合同/报告 schema 校验 100% 通过；contract_sha256 与磁盘一致
- 所有必需 AC 通过（每条有：输入、预期行为、验证方法、证据路径、Pass/Fail）
- 必需 build/typecheck/lint/test 命令退出码全部 0
- 越权文件修改 0；未授权网络访问 0；秘密泄露 0
- 新增模块依赖环 0；未记录的公共 API/schema 变更 0
- 未解决 Critical/High 缺陷 0
- 高风险任务（R2/R3）独立验证 Pass
- 已有基线问题与本次新增问题分开记录；不得以“仓库本来就有失败”掩盖本次失败

## 2. 行为验收（按适用性覆盖）

正常路径、无效输入、边界值、权限不足、空/错/慢状态、重复调用/幂等、并发、超时/重试、外部依赖失败、恢复、向后兼容。每条映射 AC/NFR 与可复核证据。

## 3. 结构审查（位置化，不评分）

审查报告必须给出：文件、位置、问题、影响、处理结果。检查项：
- 模块依赖方向符合批准方案，无未批准跨层调用
- 每个新增模块/函数单一明确职责；命名与领域术语一致，无占位名
- 无调试输出、死代码、临时绕过、未解释 TODO
- 新抽象有明确变化轴与真实使用者；无“无消费者的预留抽象”
- 注释只解释复杂意图、边界、不变量、非显然决策；不复述代码
- 安全边界、错误处理、资源生命周期可读可验证

通过阈值：未解决 blocker/major finding = 0；minor 必须修复或经用户批准豁免（含理由、残余风险、负责人、有效期）。验证者可据此给出 “PASS / FAIL / REWORK_REQUIRED”。

## 4. 风险触发独立验证

| 级别 | 触发 | 最低验证 |
|---|---|---|
| R0 | 本地、可逆、无敏感数据、无外部副作用 | AC 测试 + 静态检查 |
| R1 | 公共 API、性能、并发、持久化、模块边界 | R0 + 集成测试 + 负向测试 + 结构审查 |
| R2 | 认证/授权、PII、支付、迁移、部署、外部服务 | R1 + 新上下文独立验证 + 定向安全测试 + 性能/回滚验证 |
| R3 | 秘密、破坏性操作、生产发布、安全关键、法规 | R2 + 明确人工授权 + dry-run + 两类独立证据 |

风险类别有覆盖优先级：任何秘密读取或破坏性数据操作至少 R3，不因概率低而降级。

独立验证要求：新上下文窗口；不接收实现者主观结论；不在实现 worktree 写文件；不得修改实现后自批；只输出 Pass/Fail + 证据。

## 5. 缺陷回流

验证/集成发现的缺陷 → 生成修复合同 → 回流原实现 worktree → 新独立验证合同复验。Critical 阻断依赖任务、集成、发布、DONE。禁止只在集成分支临时修补而不回流。
